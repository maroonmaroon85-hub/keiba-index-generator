# ml/ — 機械学習パイプライン

**結論から**: 儲からない。最良の買い方（枠連 軸枠×紐枠2）で**回収率 84.5%**＝長期で15.5%ずつ減る。
ただし「モデルは市場に勝てない」は誤りで、市場（オッズ順）を10〜16pt上回る。控除率22.5〜25%の壁は越えない。
検証の全経緯・判定基準・否定された仮説の一覧は **リポジトリ直下の `HANDOFF.md`** が唯一の正。

## 実運用の3ステップ（リポ直下＝DS*.CSVがある場所で実行）
```bash
# 1. 実運用モデルを作る（オッズ入り・top3目標・シード3本平均）。データが増えたら再実行するだけ。約2分
python3 ml/train_prod.py

# 2. 出馬表から買い目を出す
python3 ml/predict.py --shutuba data/upcoming/DG260725.CSV \
                      --seiseki data/upcoming/DS260725.CSV \
                      --date 2026-07-25 --out out/reco_260725.json

# 3. レース後に答え合わせ（毎回やる。印象でなく実測で管理する）
python3 ml/check_result.py --reco "out/reco_*.json" --payout data/payout/a.csv --type wakuren
```

出力される買い目:
| | 買い方 | コスト | 実測ROI | 的中率 |
|---|---|---|---|---|
| 本命 | 枠連 軸枠×紐枠2 | 平均194円 | 84.5% | 30.0% |
| 対抗 | 三連複 BOX上位4 | 400円 | 84.5% | 20.2% |

枠連スコア（積ベース）が下位20%のレースは自動で**除外**する（84.5%→84.7%）。
これは「回収率を上げる絞り込み」ではなく「買ってはいけないレースを外す」だけ。上位に絞っても回収率は上がらない（(62)）。

**賭け金は計算しない**。全券種でROI<100%＝ケリー最適f=0%。金額は「娯楽費として許容できる額」で決めるほかない。

## モデルが2種類ある点に注意
| ディレクトリ | 作るもの | 目標 | オッズ | 用途 |
|---|---|---|---|---|
| `ml/model/` | `train.py` | win（1着） | **使わない** | 研究の初期構成。**実運用には使わない** |
| `ml/model_prod/` | `train_prod.py` | **top3**（3着以内） | **log_odds + mkt_prob** | `predict.py` が読む実運用モデル |

オッズを特徴に入れると市場を上回れるようになった（(45)）ため、実運用は後者。
どちらも生成物は `.gitignore` 済み（クローン後に学習が必要）。

## ファイル
- `features.py` — 共有の特徴量エンジニアリング（DS形式CSV→特徴量）。train系/predictで同一ロジック。
- `train_prod.py` — **実運用モデルの学習**。OOS再現の確認＋枠連の除外閾値も算出して `meta.json` に保存。
- `predict.py` — **推論**。DG（出馬表）＋DS（対象馬の過去走）＋手元の全過去データ → 買い目とJSON。
- `check_result.py` — 推奨JSONと払戻CSVの突合（枠連/三連複BOX、旧券種も読める）。
- `waku_umatan.py` — 枠番の導出（実データで99.96%検算済み）と枠連スコア（積ベース）。predictも使う。
- `place_wide.py` — 複勝/ワイドの払戻読込、ブートストラップ、共通ハイパーパラメータ `PARAMS`。
- `train.py` / `feasibility.py` — 研究初期の構成。履歴として残す。
- その他 `*_test.py` / `*_search.py` / `*_opt.py` 等は各節の検証スクリプト（HANDOFF.md の節番号に対応）。

## 予想が出ないとき
- **8頭以下** … 枠連は発売されない（実データで確認: 8頭以下1,944Rすべて配当なし）。対象外。
- **単勝オッズ未取得** … オッズはモデルの主要特徴なので予想不可。DGの出力設定に「単勝」を含める必要がある。
  TARGETの出力設定次第で**レースごとに列が変わる**（同じファイル内で23列と22列が混在する）ため、
  `predict.py` は列番号ではなく**列名**で引いている。
- **新馬戦** … 過去走が無いので順位付けできない。

## 触ってはいけない場所（一貫して裏目に出た）
モデルの精度を上げるとROIは下がる。5回とも同じ結果だった（HANDOFF (63)③）:
特徴量追加 / ハイパーパラメータ最適化 / 較正 / 過学習特徴の除去 — **いずれもAUCは改善しROIは悪化**。
`train_prod.py` のパラメータと特徴構成は「測って最良だった形」なので、理由なく変えない。
