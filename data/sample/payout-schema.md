# 連系払戻データ 仕様（Phase 4 連系バックテスト用・受領待ち）

連系（馬連/馬単/ワイド/三連複/三連単）の**回収率**を検証するために必要なデータの仕様。
戦略評価ロジック（`src/backtest/exotic-sim.ts`）と確率エンジン（`src/ev/harville.ts`）は完成・
ユニットテスト済み。**あとは払戻CSVを1レース分受領して列マッピングを確定すれば回収率が出せる。**

## 必要なのは「払戻（確定配当）」であって「オッズ全表」ではない
- 連系オッズの全組み合わせ表（3連複人気順など）は1レース数百〜800通りで巨大＝不要。
- 必要なのは**各レースの的中組み合わせと配当だけ**（1レース8個程度＝軽い）:
  単勝 / 複勝 / 枠連 / 馬連 / ワイド(3組) / 馬単 / 三連複 / 三連単。

## 内部モデル（受け取りたい形）
`RacePayout`（exotic-sim.ts）:
```
{
  umaren?:     { combo: [馬番,馬番],      payout: 100円あたり円 }
  umatan?:     { combo: [1着,2着],        payout: ... }
  wide?:       [ {combo:[a,b],payout}, ... 的中3組 ]
  sanrenpuku?: { combo: [馬番,馬番,馬番], payout: ... }   // 順不同
  sanrentan?:  { combo: [1着,2着,3着],    payout: ... }   // 着順
}
```
キーは raceId（全馬成績CSVの col41 先頭8桁と一致させる）。

## TARGETからの取得（要調査・受領後に確定）
- 払戻は「オッズ一括出力」メニューには**無い**（あそこは発走前オッズ）。
- **成績（結果）側**にあるはず。候補: レース結果画面の払戻、または 成績データのCSV出力に払戻列が含まれる形。
- JV-Data では払戻は **HR レコード**（払戻）に単勝〜三連単の的中番号＋払戻金が入る。TARGET のどのCSVがこれに当たるかを、**1レース分サンプルを出して列を確認**して確定する。
- 取得の粒度: 全馬成績と同じく**1開催日=1ファイル**の一括で出せるのが理想。

## 受領後の作業（Claude側）
1. サンプル払戻CSVの列を確認 → `src/backtest/payout-parser.ts`（新規）で `Map<raceId, RacePayout>` を作る。
2. backtest CLI に連系シミュを追加（`simulateExotic` を top1/top3 等で回し、券種別回収率を出力）。
3. Harville確率 × 実払戻 で「どの券種・何点買いが一番マシか」を実測。ML確率に差し替えればさらに精度向上。
